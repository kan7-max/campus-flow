# Campus TaskFlow βリリース前 運営チェックリスト

## 目的
- β期間中に「課題保存本体」を安定運用する。
- 外部連携の失敗で課題保存を失敗扱いにしない。
- 運営側が毎日確認すべき項目を固定化する。

## 1. β開始前（必須）
- `ADMIN_EMAILS` を設定し、運営者だけ `/admin` に入れることを確認。
- 非管理者アカウントで `/admin` / `/admin/credits` を開き、`/dashboard?admin=forbidden` に遷移することを確認。
- Supabase / Vercel / OpenAI 環境変数の設定有無を `/admin` で確認。
- Google OAuth / Calendar の callback 設定を再確認。
- `/ai -> プレビュー -> 保存 -> /assignments -> /today` が通ることを確認。
- 時間割画像取り込み導線（`/ai` 画像OCR -> 抽出確認 -> `/courses` 反映）が通ることを確認。
- `/inbox` 複数候補の個別保存が通ることを確認。
- 課題本文・`raw_text`・授業メモ・APIキー実値を運営画面に表示していないことを確認。
- `/admin/credits` で更新理由必須・監査ログ未適用時の更新拒否メッセージが出ることを確認。

## 1.5 UI/導線 品質ゲート（Preview必須）
- Preview URLでPC幅とスマホ 360px / 390px / 430px を確認する。
- `/courses`: 授業追加フォームが「授業名 → 曜日 → 時限 → 授業を保存」の順で操作できること。
- `/courses`: 横スクロールが発生せず、入力エラーが対象フィールド直下に表示されること。
- `/ai`: 課題文・授業メモのラベルが常時表示され、未入力エラーが入力欄直下に表示されること。
- `/today`: 「AI入力」を主CTAとして確認でき、作戦変更の選択肢が誤タップしにくい高さで表示されること。
- `/beta-guide`: 「3分で開始」とFAQの文言が実画面のボタン文言（「授業を保存」「選択候補を保存」「今日やること」）と一致すること。
- 不合格時は「画面名 / 操作手順 / 再現条件 / 期待との差分」を記録し、本番反映を止める。

## 2. β期間中に毎日見る指標（Tier 1）
- `/admin` の要確認アラート（失敗件数/必須サービス未設定）
- 登録ユーザー数
- AI抽出回数
- 課題保存数
- `/today` 利用状況（暫定はサーバーログ/運営メモで確認）
- Google Calendar 同期失敗数
- エラー件数（Vercelログ/Sentry候補）
- 問い合わせ件数
- データ削除依頼件数

## 3. β期間中に週1で見る指標（Tier 2）
- ログインユーザー数 / アクティブユーザー数
- AI抽出成功率 / 失敗率
- AI抽出と保存の体感遅延・失敗報告
- 通知キュー失敗率
- OpenAI / Supabase / Vercel 使用量の増加傾向

## 4. 有料化検討フェーズで見る指標（Tier 3）
- ユーザー別 AI利用量（credits/月）
- Free -> Plus/Pro の移行候補母数
- 月間コスト（OpenAI + Supabase + Vercel）/ アクティブユーザー
- API失敗率と離脱率の相関

## 5. 問い合わせ対応フロー（最小）
1. 受信時刻、ユーザー、画面URL、操作手順を記録。
2. 同時刻帯の Vercel Runtime Logs を確認。
3. 必要なら Supabase 側の対象レコード有無だけ確認（本文は収集しない）。
4. 影響範囲・回避策・再試行手順を返答。
5. 時間割画像取り込み失敗時は、`/courses` 手入力フォールバックを案内して運用継続する。

## 6. データ削除依頼対応フロー（最小）
1. 本人確認。
2. 削除対象範囲（アカウントのみ / アプリデータ含む）を確認。
3. 実施日時、担当者、実施結果を運営シートへ記録。
4. 完了連絡を返す。

## 7. プライバシー・データ取扱いルール
- 課題本文、`raw_text`、授業メモ、PDF抽出本文を外部分析イベントに送らない。
- Sentry/ログには APIキー・トークン・課題本文を載せない。
- PostHogを使う場合も入力本文をイベント化しない。
- 問い合わせメモは必要最小限の個人情報だけを記録。

## 8. 外部サービスの扱い（β時点）
- Sentry: 導入候補（エラー監視）。本格導入は段階的に。
- PostHog: 導入候補（最小イベントのみ）。
- Resend: 問い合わせ返信・運営通知候補（サーバー側のみ）。
- Stripe: βでは実装しない（checkout/webhook未導入）。

## 9. βテスター向け資料
- 資料ページ: `/beta-guide`
- PC向け: `/beta-guide?view=pc`
- スマホ向け: `/beta-guide?view=mobile`
- 不具合報告フォームと連絡先は `/beta-guide` 上のボタンから案内する。
- 公開連絡先メール: `campusflow.official@gmail.com`
- β注意: AI抽出結果は保存前に必ず手動で確認する。
